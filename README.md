# MediaSorter

按**拍摄时间**把照片和视频整理到干净的 `年/月` 文件夹,并使用 `2026-08-17_104121_001.jpg` 这样的规范文件名。
零依赖、支持拖放、跨平台(Windows / macOS / Linux)。

> 从手机(荣耀 / 华为 / iPhone)导出的照片,往往散落在 `DCIM/Camera`、微信、截屏、下载等多个目录,文件名前缀混杂(`IMG_`、`REC_`、`mmexport`、`Screenshot_`),根本无法按文件名排序。其实每张照片的拍摄时间都写在文件内部的元数据里(EXIF / MP4 元数据)——本工具把它挖出来,重新搭建成按时间排序的文件夹树。

## 为什么有三个实现?

这个仓库**有意用三种语言实现同一个想法**,各自探索不同的取舍:

| | Go(主力) | C# / .NET 4.0 | Python(已归档) |
|---|---|---|---|
| 体积 | CLI 3.5MB / GUI ~15MB | 150–400KB | 33MB(捆绑运行时) |
| 平台 | Windows · macOS · Linux | 仅 Windows | 仅 Windows |
| 运行时依赖 | 无(静态二进制) | .NET Framework 4.0(系统自带) | 捆绑 Python |
| 视频时间 | 内置 MP4 元数据解析器 | 文件时间兜底 | ffprobe(可选) |
| 状态 | **活跃** | 实验性 | 已归档(仅作参考) |

故事:它最初是一个 Python 原型,后用 Go 重写,手写 EXIF/MP4 解析器(零第三方依赖),实现跨平台单二进制交付;再用 C# 做了一次追求 150KB 极致小体积的实验(参考 [MediaSorter](https://mediasorter.com))。

## 快速开始

每次 [Release](../../releases) 都为每个平台提供**两个开箱即用的成品,无需任何编译环境**:

| 文件 | 说明 |
|---|---|
| `mediasort-gui(.exe)` | **图形界面版**(fyne)。选文件夹或**直接拖放**,点按钮即可,最适非技术用户 |
| `mediasort(.exe)` | 命令行版 / 拖到 exe 上运行 |

> 两者都由 CI 在 Windows · macOS · Linux 上自动构建。Windows 的 GUI 已静态链接,无需安装任何 DLL。

### 图形界面版(推荐大多数用户)

1. 从 [Releases](../../releases) 下载 `mediasort-gui.exe`
2. 运行它——**把照片文件夹拖到窗口上**(或用「选择」按钮)
3. 可选:目录结构 `年/月`/`仅年`/`年/月/日`、格式选择、去重、命名、录制日期筛选、时间偏移
4. 点「预览」可先看效果,确认后点「开始整理」,实时进度条+统计
5. 结果默认生成在程序旁的 `照片整理/` 文件夹

### 命令行版 / 拖到 exe 上

1. 从 [Releases](../../releases) 下载 `mediasort.exe`
2. **把照片文件夹拖到 exe 图标上松手**——无需输入任何命令
3. 结果生成在 exe 旁的 `照片整理/` 文件夹

或使用命令行:

```
mediasort <源文件夹> [目标文件夹] [选项]

选项:
  --move          移动而非复制(默认只复制,更安全)
  --no-dedupe     关闭内容去重
  --dry-run       只预览,不复制/移动/建目录
  --offset=N      时间偏移 N 秒(修正机内时间差)
  --year          仅按年分目录
  --day           按 年/月/日 分目录
```

## 功能特性

- **递归扫描**——可指向整个 U 盘;自动排除输出目录,防止递归
- **拍摄时间四级兜底**:
  1. 照片 EXIF `DateTimeOriginal`(手写 JPEG / HEIC / TIFF 解析,无第三方库)
     - HEIC/HEIF 走 ISO BMFF 的 `meta/Exif` 提取;解析失败(无 Exif item 或数据不完整)时降级到文件名/mtime 兜底,并在日志中标记来源与降级提示
  2. 视频 MP4 `creation_time`(`moov/mvhd`,UTC 自动转本地,东八区不差 8 小时)
  3. 文件名时间戳(`IMG_20260817_104121`、`Screenshot_2026-08-10-153212`、微信 unix 秒/毫秒戳)
  4. 文件创建/修改时间(取较旧者,日志中标记来源)
- **规范命名** `YYYY-MM-DD_HHMMSS_序号`——字典序等于时间序
- **内容去重**——按文件大小分组,同大小才 MD5,多 GB 视频不会全量哈希
- **安全默认**——只复制、`--dry-run` 预览、同名冲突自动加序号绝不覆盖、源文件永不删除
- **流式 I/O**——多 GB 大文件也保持常量内存
- **格式选择**——可勾选只整理 JPG / HEIC / MP4 等指定格式,或全部
- **自定义命名**——保留原始文件名,或加前缀/后缀
- **录制日期筛选**——只整理有录制日期的、或只有无录制日期的文件
- **设置自动保存**——记住上次的路径与选项,下次启动自动恢复
- **图形界面**——跨平台拖放、实时进度条与统计、预览模式
- **全流程可见进度**——扫描/去重/处理三个阶段分开反馈:扫描时显示"正在扫描…已发现 N 个"与动画进度,避免大目录(数万文件)时进度条长时间停在 0 而误以为卡住;处理阶段才切换为确定进度条。核心通过 `OnPhase` / `OnScanProgress` / `OnProgress` 回调驱动,CLI/GUI 可复用

